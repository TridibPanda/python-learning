# OOP Question & Answer

### Q1. Why do we need OOP?
We use OOP to represent real-world entities in software. OOP helps us organize data and behavior together, making the code reusable, scalable, and easier to maintain. For example, before constructing a house, we first create a blueprint. Similarly, in OOP, a class acts as a blueprint, and objects are the actual instances created from that blueprint.

### Q2. What is a Class?
A class is a blueprint or template used to create objects. It defines what data an object will have and what operations it can perform. Objects are created from a class, just like multiple houses can be built from the same architectural blueprint.

### Q3. What is an Object?
An object is an instance of a class that represents a real-world entity. Every object has two main characteristics: state (data/attributes) and behavior (methods). For example, a mobile phone is an object. Its brand, RAM, and storage represent its state, while calling, charging, and taking photos represent its behavior.

### Q4. State vs Behaviour
State represents the data or attributes of an object, while behavior represents the actions or operations that the object can perform. 
Example :
Object : Laptop 
Laptop state: Brand, RAM, Storage, Price 
Laptop behaviour: Start(), Shutdown(), Restart(), Sleep()

Object: ATM
ATM state: Balance, Account Number, PIN 
ATM behaviour: Withdraw(), Deposit(), CheckBalance()

Object: React Native Button
RN Button state: Title, Color, Width, Height
RN Button behaviour: Press(), Disable(), Enable()

### Q5. Difference between Class and Object?
A class is a blueprint or template, whereas an object is the actual instance created from that blueprint. For example, Apple first designs the MacBook M5. That design acts like a class. After manufacturing, each individual MacBook is an object. Every MacBook has its own state, such as serial number, battery level, and storage, but all of them are created from the same blueprint.
